# MySQL 读写分离 + Redis 部署说明

## 架构

| 服务 | 容器 | 宿主机端口 | 用途 |
|---|---|---|---|
| MySQL 主库 | mysql-master | 3306 | 写 |
| MySQL 从库 | mysql-slave | 3307 | 读 |
| Redis | redis | 6379 | 缓存 |

数据通过 binlog + GTID 从主库自动同步到从库。

## 启动步骤

### 1. 启动全部服务

```bash
docker compose up -d
```

首次启动时主库会自动创建复制账号 `repl`(见 `mysql/master/init/01-repl.sql`)。

### 2. 在从库上开启复制(仅首次需要)

```bash
docker exec -it mysql-slave mysql -uroot -pRoot@123456
```

```sql
CHANGE REPLICATION SOURCE TO
  SOURCE_HOST = 'mysql-master',
  SOURCE_PORT = 3306,
  SOURCE_USER = 'repl',
  SOURCE_PASSWORD = 'Repl@123456',
  SOURCE_AUTO_POSITION = 1,
  GET_SOURCE_PUBLIC_KEY = 1;

START REPLICA;
```

> `GET_SOURCE_PUBLIC_KEY = 1` 是必须的:MySQL 8.0 默认认证插件
> `caching_sha2_password` 要求加密连接,不开 SSL 时需要允许从库
> 向主库请求 RSA 公钥来加密密码,否则 IO 线程会一直卡在
> `Connecting` 并报 `error 2061`。

### 3. 加强从库只读保护(可选,推荐)

容器首次初始化不能配 `super_read_only`(会导致 root 密码设置失败),
初始化完成后手动开启,效果相同且重启后仍然生效:

```sql
-- 从库上执行
SET PERSIST super_read_only = 1;
```

### 4. 验证

```sql
-- 从库上执行,两个都必须是 Yes
SHOW REPLICA STATUS\G
-- Replica_IO_Running: Yes
-- Replica_SQL_Running: Yes
```

在主库建表写数据,从库应能查到:

```bash
docker exec -it mysql-master mysql -uroot -pRoot@123456 -e \
  "CREATE DATABASE IF NOT EXISTS test; CREATE TABLE test.t1(id INT); INSERT INTO test.t1 VALUES(1);"
docker exec -it mysql-slave mysql -uroot -pRoot@123456 -e "SELECT * FROM test.t1;"
```

验证 Redis:

```bash
docker exec -it redis redis-cli -a Redis@123456 ping
# 返回 PONG
```

## 应用连接方式

- **写操作** → `localhost:3306`(主库)
- **读操作** → `localhost:3307`(从库)
- **缓存** → `localhost:6379`,密码 `Redis@123456`

小型项目直接在代码里配两个数据源即可;以后量大了再换 ProxySQL 自动路由。

## 注意事项

- 上线前务必修改所有密码:`docker-compose.yml`、`mysql/master/init/01-repl.sql`、`redis/redis.conf`(注意 init 脚本只在数据卷为空时执行,改密码前先 `docker compose down -v` 清卷或手动改库内密码)
- 刚写入立刻读从库可能因复制延迟读不到,强一致场景读主库
- 这套是单机部署,机器宕机则主从全不可用,仅实现性能分离;要高可用需把从库放到另一台机器
- 容器内存上限在主从分别为 2G / 1G / 768M,按服务器实际内存调整 `deploy.resources.limits` 和各配置文件
